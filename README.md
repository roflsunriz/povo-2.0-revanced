# povo 2.0 プロモコード自動更新パッチ

povo 2.0（`com.kddi.kdla.jp`）で、まとめ買いしたプリペイドコードの繰り返し入力を自動化する ReVanced パッチです。povo 2.0 へのログインは必要です。

## できること

- ホーム画面に常設される黄色い「povo プロモコード自動更新」カードから、povo のメール本文をそのまま登録し、コード、商品種別、1回の有効時間、コード利用可能回数、入力期限を抽出します。
- ログイン済みの povo 2.0 API クライアントを再利用し、認証情報そのものは取得・保存しません。
- 契約情報に `start_date` と `expiry_date` がある場合は、メールから抽出した有効時間と一致するトッピングの実終端を検出します。表示用の「残り○時間」しかない場合は、初回だけ現在の終了日時を設定できます。
- 同じコードを複数回使う時間制商品（`repeatable_time_code`）だけ、終了5分前に端末を起動し、終了境界から適用成功まで安全に再試行します。単発コードは終端で再適用しません。
- 再起動、アプリ強制終了、ログインセッション失効から復旧します。失効時はコードを消費せず、再ログイン後に再開します。
- コードは Android Keystore の AES-GCM 鍵で暗号化してアプリ内へ保存します。

公式仕様上、コードの残り利用回数は確認できません。このパッチはコードの適用成功回数を端末内に記録し、サーバーの適用結果とメール記載の入力期限を正として扱います。既存版の7日24回分設定は、コード、`4/24`などの進捗、有効時間、既知終端、有効状態を保ったまま新しい商品モデルへ自動移行します。

メール本文では、商品名の固定リストより「プリペイドコード」「残り○回分」「○回分」「○時間／○日間」「即時適用」「入力期限」の文脈を優先します。公式ページの商品構成は変更されるため、既知の商品組み合わせは抽出できない場合のfallbackに限定しています。

## ReVanced Manager で使う

1. Releases の `patches.json` の URL を ReVanced Manager の「Patches」へ追加します。
2. APKM は先に単体 APK へ統合します。`base.apk` だけでは native library split が不足してインストールできません。
3. 統合した povo 2.0 APK を選択し、「プロモコード自動更新」を適用します。
4. 公式版とは署名が変わるため、通常は公式版をアンインストールしてから導入します。この操作でアプリデータが消え、再ログインが必要です。
5. パッチ版へログインし、ホーム画面下部の黄色い「povo プロモコード自動更新」カードをタップします。
6. povo から届いたメール本文全体を貼り付けます。
7. 抽出されたコード利用可能回数と1回の有効時間を確認します。途中利用から移行する場合だけ、このコードの適用済み回数を入力します。
8. 反復コードを現在利用中なら、現在の終了日時を `YYYY-MM-DD HH:mm` で入力します。
9. 「保存して有効化」を押し、商品種別、回数、有効時間、次回時刻、有効状態を確認します。正確なアラームが未許可ならAndroidの許可画面が自動で開きます。

すでに4回目などを利用中でも、そのまま登録できます。現在のトッピング中はサーバーが新規適用を拒否しますが、コードは保留され、検出した終了時刻から自動適用を始めます。

現在4回目なら、16:42の終端で5回目を自動適用します。成功ごとに現在回数を増やし、24回目の適用後は25回目を試さず自動停止します。

時間で終端が決まる同一コード型トッピングは、メールから抽出した1回の有効時間とコード回数で管理します。たとえば、コード24回の7日商品は24回、コード5回の24時間商品は5回、購入直後1回＋残り11回コードの7日商品はコードだけを11回として数えます。2時間の単発コードは保存・初回適用の対象ですが、自動反復の対象にはしません。データ容量を使い切ると時刻より前に終了するGB型は残量監視が必要であり、現在の時間終端方式の対象外です。

## 公式版を残した検証

「検証用別パッケージID」は既定で無効の開発・実機検証専用パッチです。有効にすると package を `com.kddi.kdla.jp.revanced` へ変更し、provider authority、アプリ固有 permission/action、process も同じ別IDへ変更します。ログイン redirect の URL scheme/host は変更しません。

これにより公式版 `com.kddi.kdla.jp` のアプリデータとログイン状態を残したまま並行インストールできます。検証版は別アプリ扱いなので、利用規約の確認と検証用IDへのログインは改めて必要です。本番利用用 release ではこのパッチを選択しないでください。

## 制約

Android の電源管理、圏外、povo 側障害、認証失効があるため、通信の無中断を数学的に保証するものではありません。正確なアラーム、終了前 foreground service、短間隔再試行により途切れを最小化します。

実機検証と残る確認事項は [verification.md](verification.md)、更新方法は [how-to-update.md](how-to-update.md) を参照してください。

## ビルド

JDK 21、Android SDK、GitHub Packages を読める GitHub token が必要です。

```powershell
./gradlew build
```

成果物は `patches/build/libs/patches-<version>.rvp` です。認証情報をファイルへコミットしないでください。
