# povo 2.0 プロモコード自動更新パッチ

povo 2.0（`com.kddi.kdla.jp`）で、まとめ買いしたプリペイドコードの繰り返し入力を自動化する ReVanced パッチです。povo 2.0 へのログインは必要です。

## 最初に：Managerへ貼るURL

ReVanced ManagerのURL欄には、GitHubのReleaseページや`github.com`で始まるURLを入れないでください。次のURLをそのままコピーします。

```text
https://raw.githubusercontent.com/roflsunriz/povo-2.0-revanced/main/patches.json
```

> **v0.1.0を追加済みの場合:** v0.1.0のRVPにはManager用DEXが入っておらず、URL・ローカル追加ともエラーになります。失敗したsourceと古いRVPを削除し、一覧の版が`0.1.1`以降になるよう追加し直してください。

### URLから追加する手順（自動更新あり）

1. [公式サイト](https://revanced.app/download)から最新版のReVanced Managerをインストールします。
2. Manager上部の「Patches」を開きます。
3. 右下の鉛筆ボタンを押し、続いて表示される`+`ボタンを押します。
4. 「URL」または「Remote」を選びます。
5. 上記の`raw.githubusercontent.com`のURLを貼り付けます。
6. 「Auto update」を有効にして追加します。
7. 一覧に「povo 2.0 automation patches」が表示されることを確認します。

ブラウザでraw URLを開いたとき、Webページではなく`download_url`や`version`を含むJSONが表示されれば正常です。

次のURLは入力しません。

- GitHubのリポジトリやReleaseページ
- `https://github.com/.../patches.json`
- `povo-2.0-patches.rvp`のダウンロードURL
- ブラウザで開いた後の、一時的で長いダウンロードURL

### URL追加が失敗する場合（端末から追加）

1. [povo-2.0-patches.rvp](https://github.com/roflsunriz/povo-2.0-revanced/releases/latest/download/povo-2.0-patches.rvp)をダウンロードします。
2. Managerの「Patches」→鉛筆→`+`を開きます。
3. 「Local」または「Select from storage」を選びます。
4. ダウンロードした`povo-2.0-patches.rvp`を選びます。
5. 一覧に「povo 2.0 automation patches」が表示されることを確認します。

端末からGitHubへ接続できない場合は、PCでRVPをダウンロードしてUSBやクラウドストレージで端末へ移してください。ローカル追加では自動更新されないため、新しいReleaseが出たときはRVPを入れ直します。

## このパッチでできること

- ホーム画面に常設される黄色い「povo プロモコード自動更新」カードから、povo のメール本文をそのまま登録し、コード、商品種別、1回の有効時間、コード利用可能回数、入力期限を抽出します。
- ログイン済みの povo 2.0 API クライアントを再利用し、認証情報そのものは取得・保存しません。
- povoの契約情報から、メールの商品と一致する現在の終了日時を検出します。終了日時を取得できない場合は、初回だけ手動で設定できます。
- 同じコードを複数回使う時間制商品だけ、終了5分前に端末を起動し、終了境界から適用成功まで安全に再試行します。単発コードは終端で再適用しません。
- 再起動、アプリ強制終了、ログインセッション失効から復旧します。失効時はコードを消費せず、再ログイン後に再開します。
- コードは Android Keystore の AES-GCM 鍵で暗号化してアプリ内へ保存します。

公式仕様上、コードの残り利用回数は確認できません。このパッチはコードの適用成功回数を端末内に記録し、サーバーの適用結果とメール記載の入力期限を正として扱います。既存版の7日24回分設定は、コード、`4/24`などの進捗、有効時間、既知終端、有効状態を保ったまま新しい商品モデルへ自動移行します。

メール本文では、商品名の固定リストより「プリペイドコード」「残り○回分」「○回分」「○時間／○日間」「即時適用」「入力期限」の文脈を優先します。既知の商品組み合わせは、通常の抽出ができなかった場合の予備判定にだけ使います。

## パッチ前に用意するもの

- ReVanced Manager最新版
- 未改変のpovo 2.0 APK
- povoへ再ログインできる情報
- povoから届いたプリペイドコードのメール全文

### APKM・APKS・XAPKはそのまま使えません

Managerへ渡すのは単体のAPKファイルです。次のファイルはそのまま選ばないでください。

- `.apkm`、`.apks`、`.xapk`
- APKMから取り出した`base.apk`だけのファイル
- Google Playからインストール済みのsplit APK

APKMしかない場合は、PCで[APKEditor](https://github.com/REAndroid/APKEditor/releases)などを使い、splitを単体APKへ統合します。

```powershell
java -jar APKEditor.jar m -i povo.apkm -o povo-universal.apk
```

自分が正当に入手したpovo 2.0アプリだけを使用してください。このリポジトリではpovo本体のAPKを配布していません。

## povo 2.0へパッチを適用する

1. Managerの「Apps」を開きます。
2. 「Select from storage」から、統合済みの単体povo APKを選びます。
3. パッチ一覧で「プロモコード自動更新」が有効になっていることを確認します。
4. 通常利用では「検証用別パッケージID」を有効にしないでください。
5. 「Patch」を押し、完了後に「Install」を押します。

### インストール時の重要な注意

通常版パッチは公式povoと同じパッケージID（`com.kddi.kdla.jp`）ですが、署名は公式版と異なります。公式povoが入っていると署名競合でインストールできないため、公式版を先にアンインストールする必要があります。

アンインストールするとpovoのアプリデータとログイン状態は消えます。電話回線の契約や購入済みトッピングが消えるわけではありませんが、パッチ版で再ログインが必要です。

## 初回設定

1. パッチ版povo 2.0を起動してログインします。
2. ホーム画面下部の黄色い「povo プロモコード自動更新」カードをタップします。
3. povoから届いたメールを、件名だけでなく本文全体ごと貼り付けます。
4. 抽出された商品種別、コード回数、1回の有効時間、入力期限を確認します。
5. すでに利用途中なら、このコードの適用済み回数と現在の終了日時を入力します。
6. 「保存して有効化」を押します。
7. Androidの「アラームとリマインダー」許可が表示されたら許可します。
8. 状態欄で「自動更新: 有効」、利用回数、次回時刻を確認します。

### 「適用済み回数」の数え方

数えるのは、登録する同じコードをすでに適用した回数です。

| 商品の例 | コード利用可能回数 | 設定例 |
|---|---:|---|
| データ使い放題（7日間）24回分 | 24 | 現在4回目なら`4/24` |
| データ使い放題（24時間）5回分 | 5 | 最初のコードが利用中なら`1/5` |
| 購入直後1回＋残り11回コードの7日商品 | 11 | 購入直後の即時適用中ならコード適用済みは`0/11` |
| 2時間の単発コード | 1 | 自動反復しない |

現在の終了日時は、いま利用中のトッピングが終了する日時です。メールの「入力期限」と取り違えないでください。

## 正常に動いているか確認する

設定画面で次を確認します。

- 商品種別が「時間制・反復コード」になっている
- コード回数と適用済み回数が合っている
- 現在の終了日時が未来になっている
- 「自動更新: 有効」と表示されている
- Androidの正確なアラームが許可されている

終了5分前に端末を起こし、終了境界からコードが受理されるまで再試行します。成功すると適用済み回数が1だけ増え、次回時刻が更新されます。最大回数へ到達した後は自動停止します。

## うまくいかないとき

### PatchesのURLを追加できない

- URLが`https://raw.githubusercontent.com/roflsunriz/povo-2.0-revanced/main/patches.json`と完全一致しているか確認します。
- `github.com`で始まるRelease URLは削除します。
- VPN、広告ブロックDNS、社内Wi-Fiなどが`raw.githubusercontent.com`を遮断していないか確認します。
- 失敗したsourceを一度削除し、Managerを再起動して追加し直します。
- 解決しない場合はURL追加をやめ、RVPを「Select from storage」から追加します。

### RVPを追加してもパッチが表示されない

- v0.1.0のsourceまたはRVPを削除し、v0.1.1以降を追加し直します。
- ファイル名が`povo-2.0-patches.rvp`か確認します。
- HTMLページを保存したファイルではなく、ReleaseのRVP本体を選びます。
- Patches一覧に「povo 2.0 automation patches」があるか確認します。
- bundleの版が`0.1.1`以降で、「2 個のパッチ」と表示されることを確認します。
- Managerを最新版へ更新して再起動します。

ログに`EmptyMultiDexContainerException`がある場合はv0.1.0を読み込んでいます。古いsourceを削除してから再追加してください。

### povo APKを選べない・split APKエラーになる

APKM、APKS、XAPK、`base.apk`だけのファイルは使えません。全splitを統合した単体APKを選び直します。

### インストール競合になる

公式povoまたは別の署名で作ったパッチ版が残っています。再ログイン情報を確認してから既存アプリをアンインストールし、今回作ったAPKをインストールします。

### 黄色い自動更新カードが表示されない

- 「プロモコード自動更新」パッチを選択したか確認します。
- パッチ処理が成功終了しているかログを確認します。
- povoへログインし、ホーム画面まで移動します。

### メールの数字が正しく抽出されない

保存前に商品種別、回数、有効時間、入力期限を必ず確認してください。必要なら回数・有効時間・現在終了日時を手動で修正できます。誤った内容のまま有効化しないでください。

## 更新方法

- raw URLから追加し「Auto update」を有効にした場合は、Managerが新しいRVPを取得します。
- ローカルRVPを追加した場合は、[最新Release](https://github.com/roflsunriz/povo-2.0-revanced/releases/latest)から新しいRVPをダウンロードして入れ直します。
- パッチ版povoを更新するときも、同じ署名鍵を使わない限り上書きできません。Managerのkeystoreを削除しないでください。

時間で終端が決まる同一コード型トッピングは、メールから抽出した1回の有効時間とコード回数で管理します。コード24回の7日商品は24回、コード5回の24時間商品は5回、購入直後1回＋残り11回コードの7日商品はコードだけを11回として数えます。2時間の単発コードは保存・初回適用の対象ですが、自動反復の対象にはしません。データ容量を使い切ると時刻より前に終了するGB型は、現在の時間終端方式の対象外です。

## 公式版を残した検証

「検証用別パッケージID」は既定で無効の開発・実機検証専用パッチです。有効にすると package を `com.kddi.kdla.jp.revanced` へ変更し、provider authority、アプリ固有 permission/action、process も同じ別IDへ変更します。ログイン redirect の URL scheme/host は変更しません。

これにより公式版 `com.kddi.kdla.jp` のアプリデータとログイン状態を残したまま並行インストールできます。検証版は別アプリ扱いなので、利用規約の確認と検証用IDへのログインは改めて必要です。本番利用用 release ではこのパッチを選択しないでください。

## 制約

Android の電源管理、圏外、povo 側障害、認証失効があるため、通信の無中断を数学的に保証するものではありません。正確なアラーム、終了前 foreground service、短間隔再試行により途切れを最小化します。

実機検証と残る確認事項は [verification.md](verification.md)、更新方法は [how-to-update.md](how-to-update.md) を参照してください。

## ビルド

JDK 21、Android SDK、GitHub Packages を読める GitHub token が必要です。

```powershell
./gradlew build :patches:buildAndroid
```

成果物は`patches/build/libs/patches-<version>.rvp`です。`buildAndroid`を省略するとManagerが読み込めるDEXが入らないため、通常の`build`だけで作ったRVPを配布しないでください。認証情報をファイルへコミットしないでください。
